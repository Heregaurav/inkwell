# Parts 10–11: Failure Scenarios And Design Decisions

## Part 10: Twenty Production/Development Failure Scenarios

These are plausible scenarios derived from code paths and deployment configuration, not incidents known to have occurred.

| # | Symptoms | Likely cause | Debugging and files | Fix / prevention |
|---:|---|---|---|---|
| 1 | Backend exits before accepting requests. | Mongo URI/network/auth failure or `ensureBaseData` rejection. | Inspect startup logs, env names in `backend/.env.example`, `backend/src/index.js`, `backend/src/bootstrap.js`; check DB reachability. | Validate config at boot; readiness/retry policy; alert on startup failures. |
| 2 | API health is green but data requests fail. | `/health` returns static JSON and doesn't test Mongo connectivity after boot. | Compare `/api/v1/health` with failed query logs; inspect `index.js`. | Separate liveness/readiness; readiness can test dependency with timeout. |
| 3 | Login always returns 401. | Wrong credentials, stale JWT handling, password hash issue, or wrong backend origin. | Browser network tab; `AuthPage`, `authStore.js`, `routes/auth.js`, `User.js`, Axios base URL. | Stable env/config, integration test register-login-me, avoid exposing raw error. |
| 4 | Users can log in but all protected requests return 401 after deploy. | JWT secret changed or replicas use different secret; tokens expire after 7 days. | Inspect secret injection (do not print secret), auth middleware, deployment secret references. | Shared managed secret; rotation plan/key IDs; clear token and re-auth on invalid token. |
| 5 | Forged or unexpected JWT acceptance risk. | Production fell back to known JWT secret. | Check deployment configuration presence (never output value), `middleware/auth.js`. | Fail startup if secret absent; rotate/invalidate known-key tokens. |
| 6 | Browser dev UI loads but `/api/v1` requests hit Vite and 404. | `vite.config.js` has no proxy and `VITE_API_URL` is empty. | Network tab; inspect `vite.config.js`, `utils/api.js`, backend CORS. | Add Vite proxy or set API URL; document dev setup and test it. |
| 7 | Production frontend opens but APIs fail cross-origin. | `VITE_API_URL` build-time value wrong, CORS allowlist mismatch, or deployment uses wrong host. | Inspect built config, browser network/CORS errors, `index.js`, NGINX config, Vercel config. | Same-origin reverse proxy or exact origin allowlist; rebuild with correct config. |
| 8 | Post search returns no posts while users/topics appear. | Query filters `visibility`, which is absent from Post schema and not set during create. | Inspect `routes/search.js` and `models/Post.js`; check actual stored documents. | Define/enforce visibility model or remove filter and use status/owner policy; regression test search. |
| 9 | Existing draft cannot load into editor after refresh. | `WritePage` finds ID via public posts list, whose route filters published only. | Inspect `WritePage` edit-loading effect and `GET /posts`. | Add owner-authorized `GET /posts/:id` draft route; test private draft access and reject other users. |
| 10 | `/ai/eli5` returns 500 only when `context.postId` is supplied. | Branch uses undefined `Post`, `blocksToText`, and `summarizeText`. | Inspect `routes/ai.js`; reproduce branch with mocked DB/provider. | Import/expose helpers, add route test for found/not-found post context. |
| 11 | Poll counts wrong after a traffic spike. | Concurrent read-modify-save, option index not validated, or duplicate submission. | Compare Mongo post poll map and UI; inspect post vote handler and socket events. | Atomic conditional write or unique vote collection; validate range; concurrency test. |
| 12 | Quiz answer exists but displayed aggregate is short by one. | QuizResponse insert succeeded; subsequent Post aggregate save failed. | Inspect `QuizResponse` and post counts; route logs. | Transaction or rebuildable aggregate/outbox; alert on persistence failures. |
| 13 | Two quiz requests occasionally return 500 for same user. | Unique compound index correctly rejects race, but duplicate-key isn't translated to 409. | Check Mongo duplicate-key code and quiz handler. | Catch duplicate-key and return existing-answer response; test parallel requests. |
| 14 | Follow relationship is one-sided. | Saving current user's following and target's followers is not transactional. | Inspect both User documents and `/users/:id/follow` logs. | Transaction or one authoritative follow-edge collection with derived counts. |
| 15 | Reader sees executable behavior or unexpected HTML from a post. | `dangerouslySetInnerHTML` and `new Function` process untrusted author blocks. | Stop demo execution; inspect `BlockRenderer.jsx`, stored blocks, trust provenance. | Disable runner; safe rendering/sanitization; isolated sandbox; security test/CSP. |
| 16 | Comment thread contains orphan or cross-post replies. | Route does not verify target post or that `parentId` belongs to the same post; no depth enforcement. | Inspect comment records and `routes/comments.js`; compare post and parent IDs. | Validate existence, visibility, same-post parent, max depth; route tests. |
| 17 | Socket poll update arrives only for some readers in EKS. | Event emitted on one process; room state is local and replicas lack shared adapter. | Check socket connection target, pod logs, ingress behavior; inspect `index.js`. | Shared Socket.IO adapter/pub-sub; reconnect/refetch canonical state. |
| 18 | AI summaries remain pending/failed or duplicate calls spike. | In-process work lost/restarted or each publish/update spawns another request; local dedupe does not coordinate pods. | Inspect `aiService.generatePostMeta`, pod restarts/provider logs, `aiMeta.status`. | Durable versioned jobs, idempotency, retries, concurrency caps, visible status. |
| 19 | MongoDB container is accessible from unintended host/network. | Compose publishes `27017:27017` and Mongo service has no auth config. | Inspect Compose port bindings and network/security group; don't expose DB publicly. | Bind local-only in dev; enable auth/private network; use managed DB in production. |
| 20 | New deployment appears healthy but serves stale/wrong app or loses state. | Mutable `latest` image tag, local Terraform state, Mongo PVC/backup gaps, or mismatch in cluster names. | Inspect image digest, `terraform.tfvars`, deployment script, PVC and restore status. | Immutable images, remote locked Terraform state, documented backup/restore drill, reconcile cluster names. |

**Debugging loop to say aloud:** “I’d establish the scope and timestamp, inspect client/network status and structured server logs, correlate a request/job ID, identify the owning route/model/config, reproduce with a minimal case, check stored state and query plans, then fix and add a regression test. I would avoid changing production data before preserving evidence and verifying backups.”

## Part 11: Fifteen Technical Decisions And Trade-offs

“Evidence” is directly visible in code/config. “Possible rationale” is inference; present it as an interpretation, not confirmed author intent.

| # | Decision and evidence | Possible rationale (inferred) | Alternative and trade-off | When to change |
|---:|---|---|---|---|
| 1 | React SPA with Vite (`frontend/package.json`, `vite.config.js`). | Fast component iteration and client-side app experience. | SSR/full-stack framework can improve initial HTML/SEO but adds server/runtime complexity. | SEO/initial render or data-loading requirements become central. |
| 2 | Express API separate from frontend (`backend/src/index.js`). | Independent app boundaries and familiar REST server. | BFF/full-stack framework simplifies deployment but couples UI/backend lifecycle. | Team or deployment model benefits from unified framework. |
| 3 | MongoDB via Mongoose (`models/*.js`). | Flexible block types and post-centric reads. | PostgreSQL offers relational constraints/transactions; trade-off is schema rigidity vs integrity/query capabilities. | Cross-document transaction/reporting needs dominate or measured write model struggles. |
| 4 | Embed content blocks in Post (`Post.js`). | Load complete post as one aggregate. | Separate block collection reduces document growth but requires assembly and ordering logic. | Post size or update contention reaches measured limits. |
| 5 | Embed poll/quiz aggregates and voter arrays (`Post.js`). | Fast result reads. | Separate vote records enforce uniqueness and scale write concurrency but aggregate reads cost more. | High vote volume or array/document growth. |
| 6 | Store follows/bookmarks on User arrays (`User.js`). | Fast profile/feed relationship lookup for small scale. | Edge collections scale large fan-out, but add indexes and joins. | Arrays grow large or concurrent reciprocal writes are inconsistent. |
| 7 | REST for commands plus Socket.IO event for polls (`posts.js`, `index.js`). | Durable request and timely UI updates. | Polling/SSE or durable broker; each changes latency/complexity/replay semantics. | Realtime features expand or clients need replay/cross-region behavior. |
| 8 | JWT in HttpOnly cookie (`middleware/auth.js`, `routes/auth.js`, `utils/api.js`). | Browser attaches a JWT the page cannot read; user profile remains in memory. | Reduces script-readable token exposure, but cookies are ambient and require CSRF/Origin/SameSite configuration. | Revisit cookie topology/session model if cross-site requirements or revocation needs change. |
| 9 | Bcrypt work factor 12 (`User.js`). | Adaptive password hashing. | Argon2id is a modern alternative; migration/runtime support and verification need consideration. | Security baseline or performance measurements justify update. |
| 10 | Optional Groq provider via OpenAI-compatible SDK (`aiService.js`). | Familiar SDK/API shape and AI feature optionality. | Provider-native SDK or alternate provider; compatibility does not guarantee feature/behavior parity. | Need structured output, availability, policy, latency, or price not met. |
| 11 | Heuristic fallback for AI metadata (`aiService.js`). | Core workflow remains available without provider. | Queue/retry-only policy could wait for model result but degrades immediate availability. | Product requires semantic quality or fallback misleads readers. |
| 12 | In-process background AI generation (`posts.js`, `aiService.js`). | Low implementation/ops overhead and fast publish response. | Durable queue adds delivery, retry, and worker state but improves restart resilience. | Before reliability or traffic demands production readiness. |
| 13 | Offset pagination for posts/feed (`posts.js`, `usersFeed.js`). | Easy page-number navigation and implementation. | Cursor pagination is stable/efficient at depth but changes client contract and back/forward UX. | Deep pages or large dataset make skip expensive. |
| 14 | Global in-memory rate limiter (`index.js`). | Basic abuse ceiling with no external service. | Redis-backed per-user/IP limits work across replicas but add dependency and cost. | Multiple replicas, AI cost exposure, or abuse signals require it. |
| 15 | Docker/Compose plus optional EKS/Terraform and EC2 script. | Offers local and cloud deployment paths. | Managed PaaS reduces ops; EKS adds flexibility but operational burden. | Team size, availability, compliance, cost, and traffic support a different ops model. |

### Interview Framing For Decisions

Use this sentence pattern: “The code currently does **X** (evidence: **file/function**). A reasonable reason is **Y**, though I can’t infer the original intent with certainty. The trade-off is **Z**. If workload/requirements become **condition**, I’d move to **alternative** and validate with **measurement/test**.” This protects credibility and shows engineering judgment.
